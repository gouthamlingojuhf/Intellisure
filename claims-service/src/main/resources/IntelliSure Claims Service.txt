2. Business Mission

The Claims Service manages an insured loss from:

FNOL
→ Investigation
→ Coverage Determination
→ Financial Evaluation
→ Settlement
→ Payment
→ Closure


It answers:

What happened?

Is it covered?

How much is payable?

What evidence supports the decision?

What actions remain open?

11.1 Customer Reports a Loss
Step 1

Policyholder submits FNOL

POST /api/v1/claims


Request:

{
  "policyNumber": "POL-2026-000001",
  "incidentDate": "2026-09-25",
  "incidentType": "FIRE"
}

Claims Service validates policy

Calls:

GET
/api/v1/policies/number/{policyNumber}/status


Target:

Quote & Policy Service


Response:

{
  "policyStatus": "IN_FORCE",
  "activeOnRequestedDate": true
}


If:

Policy inactive


Claim cannot move to:

COVERAGE_REVIEW

11.2 Coverage Verification

Claims must determine:

Was PROPERTY coverage active?

Was BUSINESS_INCOME coverage active?

Was LIABILITY coverage active?


Claims calls:

GET
/api/v1/policies/number/{policyNumber}/coverage-check


Target:

Quote & Policy Service


Example:

GET
/api/v1/policies/number/POL-2026-000001
/coverage-check
?coverageCode=PROPERTY
&requestedDate=2026-09-25


Response:

{
  "coveragePresent": true,
  "limitAmount": 8000000,
  "deductibleAmount": 150000
}


Claims never keeps its own policy master.

11.3 Customer Information Lookup

Claims may need:

Customer contact information
Business details
Owner information


Calls:

GET /api/customers/{customerId}


Target:

Customer & Party Service


Response:

{
  "businessName": "Goutham Restaurant",
  "ownerName": "Goutham"
}


Customer & Party remains source of truth.

11.4 Vendor Assignment

When damage requires services:

Inspection
Fire Restoration
Repair
Cleanup


Claims calls:

POST /api/v1/vendor-assignments


Target:

Vendor & Partner Service


Request:

{
  "claimId": "CLM-2026-0001",
  "serviceType": "FIRE_RESTORATION",
  "location": "Hyderabad"
}


Response:

{
  "vendorId": "VND-001",
  "vendorName": "ABC Restoration Services"
}


Claims never owns vendor eligibility.

11.5 Recovery Trigger

Business interruption discovered:

Restaurant cannot operate


Claims creates recovery work.

Calls:

POST /api/v1/recovery-triggers


Target:

Recovery Service


Request:

{
  "claimId": "CLM-2026-0001",
  "recoveryReason": "BUSINESS_INTERRUPTION"
}


Response:

{
  "recoveryTriggerId": "REC-001",
  "status": "OPEN"
}

11.6 Workflow Integration

Claims does not own work queues.

Creates:

Adjuster Assignment Task
Inspection Task
Settlement Approval Task


Calls:

POST /api/v1/workflow/tasks


Target:

Workflow & Notification Service


Example:

{
  "entityType": "CLAIM",
  "entityId": "CLM-001",
  "taskType": "ADJUSTER_ASSIGNMENT"
}

11.7 Document Storage

Evidence belongs to:

Document & Audit Service


Claims stores only references.

Uploaded document:

KitchenFirePhotos.zip


Stored:

{
  "documentId": "DOC-001"
}


Claims record:

ClaimDocumentReference
documentId = DOC-001

11.8 Analytics Integration

Loss patterns
Reserve movements
Settlement trends

To:

Analytics & Intelligence Service


Analytics returns:

Claim priority suggestions
